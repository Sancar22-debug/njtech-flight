# 实测记录

日期：2026-11-26。所有结果来自本机实际运行；没有把构建成功等同于交互通过，也没有把窄视口或合成事件称为实体手机测试。

## 环境

- 项目：Vite 7.3.8 + Three.js，本地地址 `http://127.0.0.1:5173/`。
- Qoder 内置浏览器：QoderCNApp 0.5.18，Chrome 150.0.7871.250，Electron 43.8.4，Linux x86_64。
- Qoder 视口：632×618 CSS px，DPR 1.25。这是窄视口，不记作桌面测试。
- 独立桌面浏览器：Chromium 140.0.7339.16，1440×900，截图为 `evidence/desktop-1440-fixed.png`。
- 移动布局视口：同一 Chromium，390×844，截图为 `evidence/mobile-390-fixed.png`。未使用实体手机。
- Vite 启动报告 ready in 95 ms；这是开发服务器启动时间，不是页面加载时间。

## 首版问题与修复

1. 首版浏览器出现 76 条 `Computed radius is NaN` 错误。
   - 原因：Three.js 当前版本的 `ShapeUtils.triangulateShape` 返回顶点索引，首版误当作坐标对象读取。
   - 修复：`src/world.js` 用索引从 contour 取点。
   - 回归：脚本检查 173 个建筑、校园边界、7 个水体和 68 个运动场，共 249 份几何，位置值全部有限；最终 Qoder 控制台错误为 0。
2. 390×844 首版截图中，地点条、重置/飞行按钮与附近提示挤压，按钮文字竖向换行，近处地标文字遮挡场景。
   - 修复：移动底部区域重新分层，按钮禁止换行；附近提示上移；地标按相机距离缩放并在过近/过远时隐藏。
   - 回归：390×844 与 1440×900 新截图均已人工查看，上述重叠和遮挡未再出现。
3. 初始相机天空占比偏高。
   - 修复：稳定跟随相机增加俯瞰角度，不把机翼或侧倾震动传入相机。

## 功能实测

- 首帧：Qoder 修复后一次完整 reload 测得 191 ms；此前修复后另一轮测得 267 ms。仅为本机开发模式单次记录，不是平均值或公网承诺。
- 地点卡：逸夫图书馆、厚学楼、镜湖均已打开；中英文正文、作者与许可链接存在。三张 Commons 照片分别在打开卡片时加载，实际 `naturalWidth` 为 1500、1920、1920。
- 自动导航：从地点卡点击“飞到这里”，实际抵达图书馆 approach 点并重新打开卡片。
- 手动接管：自动飞往厚学楼期间按 W，`autoNavigating` 从 true 变为 false。
- 重置：点击按钮有效；另用 `KeyboardEvent(code=KeyR)` 验证 R 键，状态立即回到 `[94.67, 58, 122.74]` 并取消导航。
- 画质：自动 → 流畅 → 精细均实际切换。632×618、DPR 1.25 下，流畅画布 632×618，精细画布 790×772。
- 触控：在 Qoder 页面发送 `pointerType=touch` 的合成 PointerEvent。摇杆持续 500 ms 使航向改变 0.298 rad，松开后回中；上升按钮持续 700 ms 使高度增加 3.324 m。此项不是实体触屏测试。
- 边界与相机：Node 中直接运行同一 `FlightController`，验证最低高度 3.4 m、最高 260 m、X/Z 边界钳制；相同位置和航向下改变 bank，相机位置与四元数不变。此项为逻辑测试，不冒充实飞完整边界路线。
- 构建：`npm run build` 成功。最终 JS 684.09 kB（gzip 184.40 kB），CSS 10.26 kB（gzip 2.90 kB）；仍有单 chunk 超过 500 kB 的构建提示。
